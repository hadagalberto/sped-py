# sped-py — SPEC

**sped**: a Python library + CLI to read, validate, write and analyse Brazilian SPED digital bookkeeping files —
**EFD ICMS/IPI**, **EFD-Contribuições**, **ECD** (contábil) and **ECF** — streaming files of several GB with constant memory,
exporting to pandas/Polars/Parquet/Excel, and running consistency checks similar to the PVA (Programa Validador e Assinador) before submission.
Open source, MIT, "Hadagalberto Junior". NOT a toy: no stubs, no TODO, no skipped or placeholder tests.

## Sources of truth (fetch and cite, never guess)
- Guia Prático da EFD ICMS/IPI (versão vigente), Guia Prático da EFD-Contribuições, Manual de Orientação do Leiaute da ECD and ECF, and the leiaute tables published by the Receita Federal (Portal SPED).
- Layout definitions live as versioned data files (`src/sped/layouts/<obrigacao>/<versao>.json`) generated by a documented script from the official tables, with source URL and date recorded. Support every layout version from 2019 to the current one, selected by the file's 0000 COD_VER.

## Core
- Streaming pipe-delimited reader: encoding detection (latin-1 is the norm; UTF-8 accepted), CRLF/LF, the `|REG|...|` framing, digital signature block (`SBMDSIG...`) detection and stripping, typed field conversion (N with decimals as `Decimal`, C, dates DDMMAAAA), per-field validation (size, required, domain tables).
- Hierarchy: build the record tree (blocos 0, B, C, D, E, G, H, K, 1, 9 / A, C, D, F, I, M, P...) with parent/child levels from the layout; iterate lazily; random access by register type with an optional on-disk index.
- Writer: produce byte-valid files, automatically recompute block closing records (x990), 9900 counts and 9999 totals.
- Validations (PVA-like): structure, required records per profile (A/B/C), totalization rules (e.g. C190 vs C170 sums, E110 apuração from C190/D190, M200/M600 for contribuições, ECD balancete I155 debits = credits), CFOP/CST/NCM table checks (bundled tables with update script), cross-block references (0150 participants, 0200 items, 0190 units used and declared). Each rule has an id, severity, message pt-BR, and a test.
- Analysis helpers: per-CFOP/CST/participante summaries, ICMS/IPI/PIS/COFINS apuração recomputation, diff between two files (retificadora vs original), merge/split by period.
- Exports: CSV per register, Parquet/Excel via extras, DataFrame accessors.

## CLI
`sped info arquivo.txt`, `sped validate arquivo.txt [--json]` (non-zero exit on errors), `sped export arquivo.txt --to parquet out/`, `sped diff a.txt b.txt`, `sped fix-totals arquivo.txt -o corrigido.txt`.

## Tests
- Synthetic but realistic fixture files per obrigação and layout version (built by a test factory, never real taxpayer data), including broken variants for each validation rule.
- Property tests: write(read(x)) byte-identical for valid files; totals recomputation idempotent.
- Performance: stream a generated 1 GB EFD with flat memory (tracemalloc bound) and throughput bound (generous).
